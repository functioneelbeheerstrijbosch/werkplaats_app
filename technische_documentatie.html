1. Architectuur & technologiestack

De applicatie bestaat uit twee zelfstandige HTML-bestanden zonder buildproces of framework — direct te openen in een browser. De backend is volledig Supabase (PostgreSQL + Auth + Realtime).
Frontend
  • Twee losse HTML-bestanden (geen build/bundler)
  • Vanilla JavaScript (ES2020+)
  • Inline CSS — geen externe CSS frameworks
  • Supabase JS SDK v2.49 via CDN
  • Werkt als PWA / mobiele webapp (geoptimaliseerd voor tablet)
Backend
  • Supabase (cloud — gehost op supabase.com)
  • PostgreSQL database
  • Supabase Auth (email + wachtwoord)
  • Supabase Realtime (websocket — live updates)
  • Supabase Storage (voor exploded views / geluidsfragmenten)
  • Row Level Security (RLS) via Supabase policies
Externe diensten
DienstGebruikVereist
SupabaseDatabase, auth, realtime, storageJa — kern van de app
Google Gemini APIAI-assistent "Rens" (diagnose-suggesties)Nee — optioneel (uitgeschakeld als sleutel leeg)

config.js inhoud

Let op voor ICT: De SUPABASE_KEY is de publieke "anon key" — dit is by design publiek. De beveiliging zit in Row Level Security (RLS) policies op de database, niet in het verbergen van de sleutel.

3. Authenticatie & gebruikersbeheer

Inloggen met e-mail + wachtwoord → Supabase Auth valideert → JWT token opgeslagen in browser → Monteur-record ophalen uit monteurs tabel → App beschikbaar
Monteur-account aanmaken
  1. Gebruiker aanmaken via Supabase Dashboard (Authentication → Users)
  2. Record toevoegen aan monteurs tabel met bijbehorende auth_user_id
  3. Velden: naam, initialen, is_admin, is_onderdelenbeheerder
Rollen
  • Monteur — standaard account, toegang tot werkplaats_app.html
  • Admin (is_admin = true) — toegang tot manager-functies
  • Onderdelenbeheerder (is_onderdelenbeheerder = true) — extra rechten in voorraadscherm

5. Werkplaats App — werking monteur (werkplaats_app.html)

Tabbladen

Wachtrij

Alle openstaande reparaties die nog niet geclaimd zijn. Monteur kan een regel claimen om hem op zijn naam te zetten (status 445 → 465).

In behandeling

Reparaties die de monteur zelf heeft geclaimd. Hier kan hij afronden, onderdelen toevoegen, tagnummers invoeren, of een regel vrijgeven.

Afgerond

Reparaties die de monteur vandaag heeft afgerond, inclusief notitie, bestede tijd en gebruikte onderdelen.

Voorraad

Taken voor het aanvullen van voorraadonderdelen. Monteur kan onderdelen afvinken als ze zijn aangevuld.

Afrond-flow (enkelvoudig)

Afronden klikken → Werkinstructie-check → Vragenlijst (indien gekoppeld) → Tagnummer invoeren (indien J) → Diagnose + werkzaamheden → Onderdelen + tijd → Opslaan in DB

Afrond-flow (bulk — meerdere regels tegelijk)

Regels selecteren → Vragenlijst per opdracht → Tagnummers per regel (indien J) → Gedeelde diagnose + werkzaamheden
(per regel bij REP-opdrachten) → Tijd per regel (uur + min) → Opslaan alle regels

6. Manager Scherm — werking beheer (werkplaats_manager.html)

Tabbladen

TabbladOmschrijving
Opdrachten verdelenLive overzicht van alle reparaties per status. Manager kan opdrachten toewijzen aan monteurs, prioriteit aanpassen, filteren op monteur/status/datum.
Onderdelen besteldOverzicht van opdrachten die wachten op onderdelen, per kleur-codering per leverancier/opdracht.
AfgerondAlle afgeronde opdrachten van de laatste 90 dagen. Samenvatting per opdracht: diagnose, werkzaamheden, tijd, gebruikte onderdelen, vragenlijst-antwoorden. Manager kan opdrachten heropenen.
DashboardProductiviteitsrapportage per monteur per dag: aantal afgeronde regels, totaal bestede tijd, gemiddelde tijd per reparatie.
TagnummersAnalysetabel van alle ingevoerde tagnummers. Filterbaar op opdrachtnr, artikelcode en tagnummer.

Heropenen afgeronde opdracht

Manager kan een afgeronde opdracht terugzetten naar de wachtrij. Status wordt teruggezet naar 450 (wachtrij), monteur-koppeling wordt verwijderd, en de opdracht verschijnt weer in de werkplaats app.

Vragenlijsten beheren

Via het manager scherm kunnen vragensets worden aangemaakt en gekoppeld aan artikelcodes of opdrachtcodes. Vraagtypes: tekst, keuze (radio), meerkeuze (checkbox), gegroepeerde checkbox. Antwoorden worden opgeslagen in de afrond-notitie en geaggregeerd weergegeven in de opdrachtsamenvatting.

7. Dataflow & koppeling tussen schermen

Hoe data van ERP naar app komt

Reparatie-regels worden aangemaakt in het ERP-systeem van Strijbosch en komen via een koppeling (of handmatige import) in de reparaties tabel van Supabase terecht. De werkplaats app leest deze data direct uit Supabase.

De huidige demo-versie ondersteunt ook handmatig aanmaken van regels (voorraadopdrachten en extra regels) direct vanuit de app.

Statusverloop reparatie

450 — Wachtrij → 445 — Aangemeld → 465 — In behandeling → 519 — Afgerond

Bijzonder: 450 = wachtrij/heropend door manager. Terugsturen naar wachtrij zet status terug op 450.

Koppeling app ↔ manager

8. Realtime synchronisatie

Beide schermen gebruiken Supabase Realtime (websockets via PostgreSQL logical replication) voor live updates zonder handmatig vernieuwen.

KanaalTabel(len)Wat het doet
werkplaats-sync (app)reparatiesToont direct wijzigingen van andere monteurs of manager (nieuw claim, statuswijziging)
manager-live (manager)reparaties, voorraad_takenManager ziet direct als monteur een regel claimt of afrondt
rens-sync-[id]rens_berichtenLive chat met AI-assistent Rens per reparatie
scherm-[monteurId]scherm_commandoManager kan commando's sturen naar het scherm van een specifieke monteur
Realtime werkt via een persistente WebSocket-verbinding. Bij verbindingsproblemen valt de app terug op periodiek herladen.

9. AI-assistent Rens

Werking
  • Gebaseerd op Google Gemini API (configureerbaar via GEMINI_KEY in config.js)
  • Context: klacht, apparaattype, artikelcode, eerdere reparaties van hetzelfde apparaat
  • Monteur stelt vragen over diagnose en mogelijke oplossingen
  • Chatgeschiedenis opgeslagen in rens_berichten tabel
Beschikbaarheid
  • Beschikbaar via detail-modal in werkplaats app
  • Niet beschikbaar voor voorraadopdrachten (soort = 'voorraad')
  • Uitgeschakeld als GEMINI_KEY leeg is in config.js

10. Tagnummer systeem

Tagnummers zijn unieke identificatiecodes per individueel apparaat. Ze worden ingevoerd door de monteur via typen of barcodescan.

Activering

Een reparatieregel krijgt tagnrscannenjn = 'J' als er tagnummers ingevoerd moeten worden. Dit wordt ingesteld:

  • Vanuit het ERP-systeem via de tagnrscannenjn kolom op de reparatie
  • Handmatig bij aanmaken van een voorraadopdracht (checkbox in het formulier)

Invoerflow

Monteur start afronden → Tagnr-scherm opent per regel → Monteur typt/scant tagnr per apparaat → Max = aantal van de regel → Opgeslagen in tagnr_scans

Analyse in manager

Het tabblad Tagnummers in het manager scherm toont alle ingevoerde tagnummers, filterbaar op opdrachtnr, artikelcode en tagnummer zelf. Kolommen: opdrachtnr, regelnummer, artikelcode, tagnummer, monteur, datum.

11. Hosting & toegang

Huidige situatie (demo)

De HTML-bestanden draaien lokaal of via een eenvoudige webserver. Ze zijn zelfstandig en vereisen geen serverside verwerking — alleen een browser met internettoegang voor Supabase.

Productie-aanbevelingen voor ICT

Supabase omgevingAparte Supabase-projecten voor productie en staging/test
RLS policiesRow Level Security instellen per tabel zodat monteurs alleen eigen data zien

ERP-koppelingData-import via Supabase REST API of directe PostgreSQL-verbinding. Reparaties worden aangemaakt in de reparaties tabel met de juiste statuscodes.
SchaalbaarheidSupabase Free/Pro schalen automatisch. Realtime ondersteunt duizenden gelijktijdige verbindingen.

12. Beveiliging

Wat al geregeld is

MaatregelToelichting
AuthenticatieInloggen via Supabase Auth (e-mail + wachtwoord). JWT-token wordt opgeslagen in de browser. Zonder geldig account is de app volledig ontoegankelijk.
HTTPS / TLSAlle communicatie verloopt versleuteld via HTTPS. Realtime-verbindingen via beveiligde WebSocket (WSS). Standaard geleverd door Supabase.
GebruikersrollenDrie rollen: monteur, admin en onderdelenbeheerder. Gekoppeld aan Supabase Auth via auth_user_id. Zonder account is de app niet toegankelijk.
Audit trailAlle acties (claimen, afronden, vrijgeven, onderdelen bestellen) worden gelogd in reparatie_logs met tijdstip en monteur. Volledig herleidbaar wie wat wanneer heeft gedaan.
Bug-meldingenMonteurs kunnen foutmeldingen indienen vanuit de app. Opgeslagen in de bug_meldingen tabel.
Geen admin-sleutel in frontendDe Supabase service-role key (volledige databasetoegang) staat nergens in de frontend-code. Alleen de publieke anon-key is aanwezig, beveiligd via RLS.
Data-afscherming na inloggenData wordt pas opgehaald nadat de Supabase Auth-sessie succesvol is gevalideerd. Zonder geldige sessie worden geen queries uitgevoerd.
